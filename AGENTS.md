# Project instructions

- Follow the implementation-only workflow. Use source inspection, TypeScript, ESLint, and production builds for verification. Do not launch or interact with a browser, start a preview server, or generate screenshots or visual previews.
- Read the relevant sections of the root `documentation.md` before modifying functionality. After each meaningful code change and its permitted verification, update the Current Implementation Reference and append a separate dated Implementation History entry. Preserve earlier entries. Append an explicit correction if an older entry is inaccurate.
- Keep `/documentation.md` ignored and out of Git. Preserve the local file through cleanup and refactors. If it is absent in a fresh checkout, recreate the local reference from verified evidence and identify history gaps. For investigation-only passes, record a note only when there is a meaningful finding.
- Mention the documentation update and any verification limitations in the final engineering handoff.
